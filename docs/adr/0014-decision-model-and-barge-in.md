# 0014. Decision model for live speech, and barge-in (M10)

## Context
The live standup decided what a participant was doing with regular expressions (`UtteranceClassifier`) and which ticket they meant with title matching (`ItemMentions`); only the update's blockers and commitments came from a model. Phrases the rules did not anticipate were missed. Separately, when someone talked over the agent it kept talking: audio already generated kept playing after the cancel, only the member whose turn it was could interrupt, and nothing acknowledged it.

## Decision
- **One call, three steps.** `IUtteranceAnalyser` reads the intent (asked, updated, stepped away, proxy, ...), the items discussed, and a comment kind per statement (blocker, date change, commitment, decision, estimate, done). One call, not three, because each model round trip costs about a second.
- **Two engines, one port.** `UtteranceAnalysis:Engine=Decision` (default) uses `DecisionUtteranceAnalyser` on a **Microsoft-Decision-1.1** deployment (`zava-decision`): typed questions (a `choice` for intent, a `choice` for the teammate named, a yes/no `noul` per open item and per comment kind) answered with probabilities, at `UtteranceAnalysis:Threshold` (0.7). It generates no prose, so the comment text is the transcript and the date is found by `SpokenDates` in code. `Engine=Chat` uses `FoundryUtteranceAnalyser`, a chat call with `agents/instructions/utterance-analyst.md`, kept as the alternative.
- **Code disposes.** `UtteranceAnalyser` (Domain) accepts a reading only at confidence 0.6 or more, keeps only roster members and sprint ids (rule 2), lets the speaker's role decide update versus chime-in, and otherwise falls back to the rules. Comment text is checked with `WorkItemIdGuard`. This relaxes the earlier "item links come from code only" rule: the model may now name an item, but never one outside the sprint.
- **Events.** When the model read every segment of an update, its comments become the recorded events and the reconcile model's own events are not used, so a statement is classified once. `StandupEventType.DateChange` is new and recorded only; nothing in Azure DevOps changes.
- **Latency budget.** `UtteranceAnalysis:TimeoutMs` (default 2500) bounds the wait; a slower or failed answer (including 429) is dropped and the rules decide. `Mode=Rules` restores the earlier behaviour. Measured: the decision model answers in 0.6 to 1.3 s (chat model 2.5 to 3 s); the whole analysis step takes 1.4 to 2.5 s because it runs before the floor reacts. In the Simulated Room e2e the p50 agent latency went from 4.2 s (rules) to 6.2 s, and 11 of 19 utterances were read by the model, the rest hit the budget and used rules.
- **Deployment.** The deployment is created with the CLI, not Bicep (the template only references Foundry): `az cognitiveservices account deployment create --name fdy-mcm-scrum-demo --resource-group rg-mcm-scrum-demo-wus3 --deployment-name zava-decision --model-name Microsoft-Decision-1.1 --model-format Microsoft --model-version 1 --sku-name GlobalStandard --sku-capacity 100`. Capacity is the rate limit (capacity 10 is 10 requests and 10,000 tokens a minute, which a live standup exceeds), and a capacity change takes a few minutes to be enforced.
- **Barge-in.** The gateway drops audio from the cancelled response until the next response starts, sends `conversation.item.truncate` for what was played, identifies the interrupter from the live speaker instead of the presenter, arms a shorter confirm (`Voice:BargeInMs`, 350) and lets a non-holder cut in after `Voice:SustainedBargeInMs` (1500). The next agent turn gets a note that it was interrupted, by whom and while saying what.
- `POST /api/sessions/{id}/analyse` shows a reading without a live call, to tune the prompt.

## Consequences
- Each utterance can wait up to the budget before the agent responds; the p50 latency metric rises when the model is on.
- Each reading is a fresh stateless call, so a deployment problem shows up as the rules deciding, never as a failed standup.
- `// VERIFY:` `conversation.item.truncate` on Voice Live. A refusal is logged, not shown in the room. Not yet checked live in Teams.
- Opening and recap are still not interruptible, so the floor never ends up with nobody holding it.
