# 0009b. Microsoft Agent Framework agents and basic OpenTelemetry

## Context
ADR 0002 kept the first agent adapters on a hand-written `HttpClient` call to the Foundry chat route, because the M1 agent had no tools, memory or loop and a framework added packages for no demo value. The stack rules and the production design call for Microsoft Agent Framework (MAF) over the Foundry v2 SDK, and nothing in the repo reported telemetry even though Bicep already sets `APPLICATIONINSIGHTS_CONNECTION_STRING`.

## Decision
- **Move the four agent adapters (`FoundryBacklogRiskAgent`, `FoundryReconcileAgent`, `FoundryReportingAgent`, `FoundryDraftingAgent`) onto MAF chat-client agents.** Only their shared call changed. `FoundryChat` keeps its `IsConfigured` and `TryCompleteJsonAsync(system, user, ct)` surface; it now creates an `AIAgent` through `IFoundryAgentFactory` and calls `RunAsync` with JSON response format and a token cap.
- **`FoundryAgentFactory`** builds code-defined Responses agents with `AIProjectClient.AsAIAgent(model, instructions, name)` from `Microsoft.Agents.AI.Foundry` 1.5.0 over `Azure.AI.Projects` 2.0.1 and `Microsoft.Agents.AI` 1.28.0, authenticated with the existing `DefaultAzureCredential`. No server-side agent resource is created, so prompts still come from `agents/instructions` at call time (rule 5). The agent is wrapped with `UseOpenTelemetry`.
- **Ports, Application and Domain are unchanged.** The port interfaces, handlers and the guards on model output (`WorkItemIdGuard`, `CeremonyPack.IsGrounded`) did not move. The packages are referenced only by `Mcm.Scrum.Infrastructure` (and the telemetry package by the Api); the architecture tests still pass.
- **Fallbacks are kept and widened.** Any exception other than the caller's own cancellation (timeout, HTTP 4xx or 5xx, no credential, malformed reply) logs a warning and returns `null`, so the caller uses its code fallback. The per-call timeout is now `Foundry:TimeoutSeconds` on a linked cancellation token instead of the `HttpClient` timeout.
- **JSON mode needs the word "json" in the input message** on the Responses API (found in a live run: HTTP 400 otherwise), so `FoundryChat` appends a one-line reminder to the user message. The prompt files are unchanged.
- **Basic OpenTelemetry** (`Mcm.Scrum.Api/Telemetry`): `Azure.Monitor.OpenTelemetry.AspNetCore` 1.6.0 exports ASP.NET Core requests and outgoing HTTP, one span per use case (`LoggingBehavior`, source `Mcm.Scrum.Application`) and the MAF model calls (source `Mcm.Scrum.Agents`). It is registered only when `APPLICATIONINSIGHTS_CONNECTION_STRING` is set, so local runs and tests need no setup.
- **Tests.** The agent tests now run a real MAF `ChatClientAgent` over a fake `IChatClient`, covering the parse paths, the outage and not-configured fallbacks, the prompt reaching the agent as instructions, and caller cancellation.

## Consequences
- Four more NuGet packages (and their transitive OpenAI and Azure.AI.Projects.Agents dependencies) in Infrastructure; versions are pinned centrally. `// VERIFY: https://learn.microsoft.com/agent-framework/integrations/by-component/model-providers/microsoft-foundry` (package and API names move quickly).
- Behaviour was checked live against the Foundry project: the pre-brief summary and questions, Teams-style Q&A, the sprint report and Story Writer all came from the model with no fallback, and `npm run e2e --prefix src/meeting-bridge` passes (6 checks). The reconcile agent was exercised by that e2e through the Simulated Room; it is not separately asserted on the model's wording.
- `DefaultAzureCredential` can stall for about 20 s on a machine with no instance-metadata network. Set `AZURE_TOKEN_CREDENTIALS=dev` locally to skip managed-identity probing. `// PROD: ManagedIdentityCredential.`
- Telemetry was built and unit-neutral; it has not been checked in a live Application Insights resource and has no custom metrics, sampling or bridge traces. `// PROD:` sampling, per-ceremony metrics, bridge-to-API trace propagation.
- Not done: Foundry hosted agents, agent tools or memory, and Agent Framework workflows. The model still only phrases text from facts computed in code.
