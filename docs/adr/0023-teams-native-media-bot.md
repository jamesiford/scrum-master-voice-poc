# ADR 0023: Teams-native media bot

Date: 2026-11-26. Status: implemented as a selectable alternative; deployment and live acceptance belong to conductor step 6b.

## Context

ADR 0015 S5 left both the permission and VM choice open. S6 measured a relay round trip, not participant attribution or a real media call. The requested non-recording rule is stronger than "do not save PCM": [Graph's recording-status reference](https://learn.microsoft.com/en-us/graph/api/call-updaterecordingstatus?view=graph-rest-1.0) prohibits persisting media **or data derived from it** before a successful recording-status notification. Passing media into the existing gateway, which saves transcript events and follow-ups, would violate that rule.

## Decision

Keep `IMeetingBridge` and Application unchanged. `Bridge:Mode` selects `Acs`, `GraphMedia` or `Simulated`; the last uses the existing browser room, never a fabricated Teams join. ACS stays the default and keeps the complete approval demo.

`Zava.Scrum.MediaBot` is a real Windows/x64 application-hosted media client. It parses the stored calendar link into Graph meeting coordinates, validates the session and explicit team at the API before joining, uses the SDK's built-in authenticated callback processing, follows call/own-participant lobby notifications, and deletes the call on the existing `StandupEnded` lifecycle. Short links preserve literal and escaped plus signs in passcodes. A bounded reconnect retries the API connection twice after the first attempt while retaining the real Graph call; the ephemeral conversation restarts, not resumes.

Use the per-meeting application RSC permission `Calls.JoinGroupCalls.Chat` for joining, plus tenant-admin-consented `Calls.AccessMedia.All`. The [create-call reference](https://learn.microsoft.com/en-us/graph/api/application-post-calls?view=graph-rest-1.0) explicitly requires the latter for application-hosted media. The [calling-bot registration guide](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/registering-calling-bot) also lists `Calls.AccessMedia.Chat`; these pages are not consistent enough to claim a wholly RSC media grant. We do not grant tenant-wide joining. Step 6b must verify installation/consent with the actual tenant.

Unmixed source ids are mapped through the SDK participant's audio streams to its user object id, only when its tenant matches. Domain `ParticipantAttribution` requires a unique active match in the requested team. Missing tenant/id, duplicate identities and same-name guests stay guests. The gateway selects the strongest unmixed frame for the single Voice Live input stream; overlapping speakers therefore need the G2 check, not an invented accuracy claim. Guests are visible in the live portal but their PCM is not sent to the model and they receive no member facts or approval tools.

An independently authenticated API `/invocations_ws` carries identity-tagged JSON PCM to `GraphMediaVoiceGateway`, which uses the existing hosted `VoiceLive:RelayEndpoint`. The gateway has read-only context and the shared Domain `FloorControl`, but no mediator, writable ports or executable tools. All incoming/return PCM, model conversation and parking data remain in bounded process memory and are cleared on disposal. It stores no transcript, spoken update, voice-derived attendance or proposed change. Normal session lifecycle metadata and existing metadata-only lifecycle cards remain separate; they cannot contain learned meeting updates.

The sustained-speech path sends `stopAudio`, cancels the model response, discards late audio/done events, and truncates the interrupted item using the host's played-frame acknowledgement. The existing Domain exceptions for opening, recap and absent-member announcements are retained, rather than changing shared floor rules in this adapter PR. The live 500 ms acceptance and the agent's answer to the interruption are **not measured**; step 6b must explicitly exercise these states and record any mismatch.

Pin `Microsoft.Graph.Communications.Calls.Media` 1.2.0.18742; it pulls `Microsoft.Skype.Bots.Media` 1.33.0.258-preview transitively. Do not add the latter directly (the spike hit NU1605). The current SDK supports `AudioFormat.Pcm24K`: PCM16 mono at 24 kHz, 960 bytes per 20 ms, so no resampler is added. The [conceptual media page](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/real-time-media-concepts) describes 16 kHz and discourages raw-media bots for AI agents. This alternative follows the requested native-media experiment, not a claim that Microsoft recommends it for an AI deployment.

Opt-in hosting is a public Windows Server 2022 `Standard_D3_v2` VM, four vCPU, hard cap one call pending the later video-encoder measurement. [Hosting requirements](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/requirements-considerations-application-hosted-media-bots) require Windows on Azure, an instance public IP and a trusted certificate. The [debugging guide](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/debugging-local-testing-calling-meeting-bots) documents TCP 8445; expose only HTTPS 443 and media TCP 8445, not a guessed UDP range. The VM module uses a NIC subnet because Azure requires it, not private endpoints or a private-network design. Key Vault, scoped managed-identity roles, hash-verified artefact delivery and a SYSTEM startup task are scripted. Certificate acquisition and meeting RSC installation are named human gates in DEPLOY.md.

## Evidence and consequences

- Local checks: identity rule 4/4, Windows coordinates/amplitude 8/8, real-mediator GraphMedia bridge 3/3, ephemeral gateway guest/cross-talk/cancel/truncate/producer-cleanup 4/4, media capability/ownership 3/3, existing API sign-in classification 1/1, architecture 14/14. These are test cases, not live meeting samples.
- The SDK freshness check confirms the pinned version is the latest, published 2026-10-31. CI runs daily and fails a non-latest pin older than three months.
- No Windows VM deployed, no new hourly resource cost (USD 0/hour). G1, G2, G6 and live barge-in have sample size zero in this step. Historical ACS/relay figures are not GraphMedia measurements.
- GraphMedia cannot deliver saved meeting-derived follow-ups under the non-recording requirement. A future recording feature needs a separately approved design, successful `updateRecordingStatus` first, and the applicable recording policy/certification; that call alone is not a blanket permission to record.
- Step 6b owns public TLS/bootstrap verification, real tenant/RSC behaviour, unmixed identity mapping, lobby and reconnect observations, ten joins and per-hop latency. Keep ACS selectable if any gate fails; do not silently widen joining permissions or change the default.
