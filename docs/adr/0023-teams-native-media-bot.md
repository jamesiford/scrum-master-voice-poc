## Context

ADR 0015 S5 left both the permission and VM choice open. S6 measured a relay round trip, not participant attribution or a real media call. The requested non-recording rule is stronger than "do not save PCM": [Graph's recording-status reference](https://learn.microsoft.com/en-us/graph/api/call-updaterecordingstatus?view=graph-rest-1.0) prohibits persisting media **or data derived from it** before a successful recording-status notification. Passing media into the existing gateway, which saves transcript events and follow-ups, would violate that rule.

## Decision

Keep `IMeetingBridge` and Application unchanged. `Bridge:Mode` selects `Acs`, `GraphMedia` or `Simulated`; the last uses the existing browser room, never a fabricated Teams join. ACS stays the default and keeps the complete approval demo.

`Zava.Scrum.MediaBot` is a real Windows/x64 application-hosted media client. It parses the stored calendar link into Graph meeting coordinates, validates the session and explicit team at the API before joining, uses the SDK's built-in authenticated callback processing, follows call/own-participant lobby notifications, and deletes the call on the existing `StandupEnded` lifecycle. Short links preserve literal and escaped plus signs in passcodes. A bounded reconnect retries the API connection twice after the first attempt while retaining the real Graph call; the ephemeral conversation restarts, not resumes.

Use the per-meeting application RSC permission `Calls.JoinGroupCalls.Chat` for joining, plus tenant-admin-consented `Calls.AccessMedia.All`. The [create-call reference](https://learn.microsoft.com/en-us/graph/api/application-post-calls?view=graph-rest-1.0) explicitly requires the latter for application-hosted media. The [calling-bot registration guide](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/registering-calling-bot) also lists `Calls.AccessMedia.Chat`; these pages are not consistent enough to claim a wholly RSC media grant. The dedicated app's `Calls.AccessMedia.All` grant was made and read back during the authorised administrator window. We do not grant tenant-wide joining. Catalogue publication was attempted but Graph refused the Azure CLI token's missing delegated catalogue scopes; organiser installation/RSC remains unverified.

Unmixed source ids are mapped through the SDK participant's audio streams to its user object id, only when its tenant matches. Domain `ParticipantAttribution` requires a unique active match in the requested team. Missing tenant/id, duplicate identities and same-name guests stay guests. The gateway selects the strongest unmixed frame for the single Voice Live input stream; overlapping speakers therefore need the G2 check, not an invented accuracy claim. Guests are visible in the live portal but their PCM is not sent to the model and they receive no member facts or approval tools.

An independently authenticated API `/invocations_ws` carries identity-tagged JSON PCM to `GraphMediaVoiceGateway`, which uses the existing `IVoiceSessionFactory`: Direct and Hosted are both supported real routes. The deployed Direct default is retained; a hosted relay is not required by the code. The gateway has read-only context and the shared Domain `FloorControl`, but no mediator, writable ports or executable tools. All incoming/return PCM, model conversation and parking data remain in bounded process memory and are cleared on disposal. It stores no transcript, spoken update, voice-derived attendance or proposed change. Normal session lifecycle metadata and existing metadata-only lifecycle cards remain separate; they cannot contain learned meeting updates.

The sustained-speech path sends `stopAudio`, cancels the model response, discards late audio/done events, and truncates the interrupted item using the host's played-frame acknowledgement. The existing Domain exceptions for opening, recap and absent-member announcements are retained, rather than changing shared floor rules in this adapter PR. The live 500 ms acceptance and the agent's answer to the interruption are **not measured**; step 6b must explicitly exercise these states and record any mismatch.

Pin `Microsoft.Graph.Communications.Calls.Media` 1.2.0.18742 and directly reference its matching `Microsoft.Skype.Bots.Media` 1.33.0.258-preview dependency. The earlier spike's mismatched direct pin caused NU1605; avoiding a direct reference made local managed builds pass but omitted the native payload because the package uses `build`, not `buildTransitive`, assets. Actual Windows startup failed with `DllNotFoundException: NativeMedia`. The aligned direct pin imports the vendor's native-payload targets; publish checks the DLL before upload. Keep both central pins aligned when upgrading. The current SDK supports `AudioFormat.Pcm24K`: PCM16 mono at 24 kHz, 960 bytes per 20 ms, so no resampler is added. The [conceptual media page](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/real-time-media-concepts) describes 16 kHz and discourages raw-media bots for AI agents. This alternative follows the requested native-media experiment, not a claim that Microsoft recommends it for an AI deployment.

Opt-in hosting is a public Windows Server 2022 `Standard_D4s_v5` VM, four vCPU, hard cap one call pending the later video-encoder measurement. ARM refused D3_v2 in westus3 despite available quota; D4s_v5 was unrestricted, validated and deployed without requesting quota. [Hosting requirements](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/requirements-considerations-application-hosted-media-bots) require Windows on Azure, an instance public IP and a trusted certificate, not a separately owned DNS suffix. The [debugging guide](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/calls-and-meetings/debugging-local-testing-calling-meeting-bots) documents TCP 8445; expose HTTPS 443 and media TCP 8445, not a guessed UDP range. TCP 80 supports a temporary HTTP-01 listener. Let's Encrypt issued the Azure DNS-label certificate and the VM identity imported it into Key Vault; the Teams media handshake remains unverified. The VM module uses a NIC subnet because Azure requires it, not private endpoints or a private-network design. Key Vault, scoped managed-identity roles, hash-verified artefact delivery and a SYSTEM startup task are scripted. Rerun the hook monthly for certificate renewal; there is no unattended renewal scheduler.

## Evidence and consequences

- Local checks: identity rule 4/4, Windows coordinates/amplitude 8/8, real-mediator GraphMedia bridge 3/3, ephemeral gateway guest/cross-talk/cancel/truncate/producer-cleanup 4/4, media capability/ownership 3/3, existing API sign-in classification 1/1, architecture 14/14. These are test cases, not live meeting samples.
- The SDK freshness check confirms the pinned version is the latest, published 2026-10-31. CI runs daily and fails a non-latest pin older than three months.
- Real startup also required explicit `SetServiceBaseUrl("https://graph.microsoft.com/v1.0")`, as in the [official local-media samples](https://github.com/microsoftgraph/microsoft-graph-comms-samples/tree/master/Samples/V1.0Samples/LocalMediaSamples). Managed unit tests did not exercise native platform/client construction; live hosting exposed both this omission and the missing native payload.
- Hosting in zavaw3: public Windows VM, static IPv4, 127 GB Standard SSD, vault, private artefact container and F0 calling bot. Verified westus3 fixed rates: Windows VM USD 0.376/hour, IP USD 0.005/hour, E10 disk USD 9.60/month; total about USD 0.39415/hour or USD 287.73 per 730-hour month, plus operations/storage/egress.
- Actual SDK/HTTPS readiness reports `recording=false`, cap 1, and survives an idle VM reboot without manual task start. The task is running as SYSTEM with one at-startup trigger; scoped VM vault/container roles read back. This is not a media handshake or concurrent-call load test.
- Native G1/G2/G6 and real-human barge-in: n=0. The stored schedule has no real meeting link; Daniel/Maya lack roster Entra object ids; catalogue/RSC installation is outstanding. Historical ACS/relay figures and Simulated Room regression measurements are not GraphMedia measurements.
- Direct Simulated Room before/after: one run and 11 timed turns each, zero talk-overs. Total p50/p95 3419/4435 ms before and 3311/5115 ms after; tail increased 15.3%, largely orchestration, failing the historical 10% p95 tolerance on this point estimate. Full per-hop figures and source/deployed-image distinctions are in the gate table. Mandatory verification passed health/auth, approved Azure DevOps write and audit chain; this is not native G1 evidence or proof of a native-hop regression. Retain the unchanged Direct/ACS defaults.
- Synthetic gateway probes: 7/7, including 90/90 already identity-tagged frames (30 per identity), strongest-guest overlap suppression, and stop dispatched 29.6 ms after the 350 ms threshold (n=1), cancelled/truncated at 120 played ms. These do not measure SDK attribution, audible cessation or a spoken answer. Opening-state speech sustained for 600 ms does not cancel: unconditional barge-in fails synthetically because the shared floor exception is retained.
- GraphMedia cannot deliver saved meeting-derived follow-ups under the non-recording requirement. A future recording feature needs a separately approved design, successful `updateRecordingStatus` first, and the applicable recording policy/certification; that call alone is not a blanket permission to record.
- Before selecting native for a live demo, complete the exact catalogue/calendar/roster/RSC actions in DEPLOY.md and measure unmixed identity mapping, lobby/reconnect, ten joins, human interruption and native per-hop latency. Keep ACS as the default; do not silently widen joining permissions or claim one-call health is a capacity load test.
